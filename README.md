# StereoFix Web для iPhone

**Вебзастосунок для Safari, який перетворює стереозапис із DJI Mic Mini (і не лише) на моно. Без Xcode, IPA та сервера для ваших відео.**

> Статус: перша тестова версія. Логіка команд FFmpeg перевірена локально на тестовому відео. Повна збірка Vite та виконання у Safari на реальному iPhone не перевірені у цьому середовищі.

## Можливості

| Режим | Результат |
| --- | --- |
| Обидва в моно | Лівий та правий мікрофони змішуються в один канал (кожен з коефіцієнтом 0,5) |
| Тільки лівий | Залишається лівий канал, виводиться по центру |
| Тільки правий | Залишається правий канал, виводиться по центру |
| Розділити | Два окремі монофайли `MIC1_left.m4a` і `MIC2_right.m4a` для CapCut |

Відеопотік MOV/MP4 **копіюється без перекодування** (`-c:v copy`). Аудіопотік перекодовується в AAC моно, оскільки його вміст змінюється. Для аудіофайлу на вході отримуєте M4A, а не відео.

Обробка проходить на пристрої через FFmpeg.wasm. Вхідні файли НЕ передаються на сервер; вебсервер надає лише HTML, JavaScript і модуль FFmpeg.

## Запуск без Xcode через GitHub Pages

Потрібен лише обліковий запис GitHub і браузер на комп'ютері для першої публікації.

1. Перейдіть на https://github.com/new і створіть **публічний** репозиторій із назвою `stereofix-web`. Не обов'язково додавати README при створенні.
2. Розпакуйте ZIP. Вивантажте **всі файли й папки зсередини StereoFix-Web без зовнішньої папки** в корінь репозиторію. Важливо включити приховану папку `.github` із файлом `.github/workflows/deploy.yml`.
3. Відкрийте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Якщо GitHub просить підтвердити дію, підтвердіть.
4. Перейдіть до **Actions → Publish StereoFix web app** і запустіть **Run workflow** (або дочекайтеся автоматичного запуску від завантаження файлів). Перший запуск встановить залежності й збере сайт.
5. Після успішного виконання посилання з'явиться у **Settings → Pages**. Зазвичай це `https://<github-username>.github.io/stereofix-web/`, але точну URL дивіться в Pages.
6. Відкрийте адресу у Safari на iPhone, виберіть ролик, режим і натисніть **Обробити відео**.
7. Якщо хочете ярлик, у Safari натисніть **Поділитися → На початковий екран → Додати**.

**Не відкривайте `index.html` напряму як `file://`**: браузер блокує необхідні модульні Web Workers для FFmpeg. Потрібен HTTPS-сайт, наприклад GitHub Pages.

### Альтернатива з терміналом на Mac, Windows чи Linux

```bash
npm install
npm run dev
```

Після перевірки:

```bash
npm run build
```

Готова статична версія буде у папці `dist/`. Її можна завантажити на будь-який HTTPS-хостинг без серверної логіки. Зверніть увагу: `public/vendor/ffmpeg/` заповнюється автоматично перед production-збіркою через `script/copy-core.mjs`.

## Використання на iPhone

1. Відкрийте розміщений StereoFix у Safari.
2. **Вибрати файл** → «Фототека» або «Файли».
3. Оберіть один із 4 режимів.
4. Натисніть **Обробити відео** і не перемикайтеся із Safari до завершення обробки.
5. **Завантажити** або **Поділитися** → «Зберегти у Файли».
6. Для режиму «Розділити» додайте обидва M4A до CapCut як окремі доріжки та вимкніть оригінальний звук відео.

## Важливі обмеження

- Почніть із короткого MOV/MP4 до 100 МБ. Великі 4K-відео можуть призвести до помилки пам'яті Safari, навіть якщо в них лише копіюється відеопотік. Весь файл доводиться завантажувати в пам'ять WebAssembly.
- Для функцій `right` і `split` потрібен запис із двома каналами. Для монофайлу другого каналу не існує.
- Для першого запуску потрібен інтернет і завантаження WebAssembly-компонента розміром приблизно 30 МБ. Після цього файли можуть кешуватися, але надійна офлайн-робота залежить від обмежень Safari.
- Не всі вхідні відеокодеки сумісні з контейнером MP4. MOV зберігається як MOV; нестандартні відеоформати можуть не експортуватися.
- У результаті для режимів `mix`, `left`, `right` буде **один моноаудіоканал** (1 channel). Під час прослуховування він звучатиме в обох навушниках.
- Браузер може не підтримувати завантаження чи поширення дуже великих результатів. Використовуйте кнопку «Поділитися» там, де вона доступна.
- Процедура не повертає можливість окремого регулювання голосів при виборі «Обидва в моно»: для цього вибирайте «Розділити».
- GitHub отримує тільки програмний код. Ваші відеофайли не завантажуються в репозиторій.

## Технічні деталі

- Vite 5, JavaScript, CSS, Progressive Web App
- `@ffmpeg/ffmpeg` та single-thread `@ffmpeg/core` версії `0.12.10`
- Без `SharedArrayBuffer` / налаштувань COOP і COEP для мультитредінгу
- `-c:v copy`, `-c:a aac`, `-ac 1`, `pan=mono|...`
- Автоматична збірка і розгортання на GitHub Pages через GitHub Actions

### Локальний тест фільтрів FFmpeg

Якщо у вас є ffmpeg / ffprobe:

```bash
./tests/test-audio-filters.sh
```

Скрипт генерує тестовий MP4 із 440 Гц в лівому каналі і 880 Гц у правому та перевіряє вихідні файли всіх чотирьох режимів.
